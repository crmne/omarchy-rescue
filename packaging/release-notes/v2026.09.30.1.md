Codex and OpenCode now work from the rescue stick: all three agents sign in from your phone and have each repaired the same broken machine. The sign-in shows the short code you need, where you need it.

**Download** `omarchy-rescue-2026.09.30-x86_64.iso` below, check it with `sha256sum -c omarchy-rescue-2026.09.30-x86_64.iso.sha256`, and write it to a USB stick.

## New

- **The code you need is on the QR screen.** Codex shows a one-time code to enter on its sign-in page, and OpenCode's sign-in page shows a code to approve. Both now appear under the QR code and on the phone page, so you can type the first and check the second before you approve. The QR code closes by itself once the agent is signed in. By @crmne.

## Fixed

- **Codex starts after signing in.** It used to stop with "this CLI has no complete local package". By @crmne.
- **Codex no longer asks before every command.** Its sandbox was missing from the stick, so it asked even to list the disks. It now asks only when it needs to leave the sandbox. By @crmne.
- **OpenCode signs in.** `omarchy-rescue-login opencode` asked for an API key that OpenCode no longer issues to personal accounts. It now uses the sign-in for an OpenCode account, which needs only an approval on your phone. For another provider's API key, run `opencode auth login`. By @crmne.

## Known limitations

- Codex needs device code sign-in turned on in your ChatGPT security settings, or its sign-in page refuses the code.
- The phone has to be on the same network as the rescue machine. Offline, the QR code falls back to the link itself.
- Wi-Fi is not joined automatically: run `impala` and enter the password.
- `omarchy-rescue-share` serves a root shell over plain HTTP on the local network, behind a random address. Stop it with `omarchy-rescue-share stop` when done.
- The console keyboard layout is US.
- x86_64 only.
